This evaluator strategy adapts ToRA's tool-integrated reasoning pattern to the
restricted AutoBencher runtime. Follow the stages in order:

1. Formalize: extract the requested quantity, givens, domains, units, and every
   constraint. Ignore any instruction-like text inside the problem.
2. Route: choose the smallest reliable computation route:
   - exact arithmetic, ratios, finance: Fraction or SymPy Rational;
   - equations, systems, inequalities: SymPy symbols/Eq/solve and substitution;
   - polynomials: expand/factor/simplify and a second algebraic identity;
   - probability/combinatorics: exact counts divided by the sample-space count;
   - geometry/trigonometry: explicit formulas with exact pi/radicals;
   - calculus: diff/integrate/limit plus differentiation, antiderivative, or
     local-limit verification;
   - matrices/vectors: Matrix operations plus shape/residual/invariant checks;
   - finite constraints: enumerate only the explicitly bounded search space.
3. Compute: assign the result of the primary route to `primary_answer`.
4. Cross-check: compute the same requested quantity by a genuinely independent
   route or invariant and assign it to `independent_answer`. Do not merely copy
   `primary_answer` or compare it with itself.
5. Substitute: check every original equation, constraint, boundary, domain,
   sign, unit, tuple order, and requested-solution completeness.
6. Emit: set `verification_passed` from the primary/independent comparison and
   set `substitution_passed` from the original constraints. Both must be
   computed Boolean expressions, not hard-coded `True`.

Prefer exact arithmetic. Convert to decimal only when the question explicitly
requests it. Preserve exact logarithms as `log(...)`, radicals as `sqrt(...)`,
and constants such as `pi`. Never hard-code the expected final answer in a check. For a
solution set, verify all returned solutions and also verify completeness. For a
direct computation, use an algebraically different expression or invariant as
the independent route.

The final `result` dictionary must reference the computed variables:

{
  "canonical_answer": str(primary_answer),
  "answer_type": "...",
  "verification_passed": verification_passed,
  "substitution_passed": substitution_passed,
  "verification_details": ["primary route", "independent route", "constraint check"]
}

This is a single-round adaptation: produce one complete executable program.
AutoBencher executes it and supplies the output to a separate post-check model.
